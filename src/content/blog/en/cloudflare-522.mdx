## What does Cloudflare 522 mean?

A 522 error is a **Connection Timed Out** response generated by Cloudflare, not your origin server.

The key distinction: the user's browser successfully reached Cloudflare. Cloudflare then tried to open a TCP connection to your origin server and received no response within the timeout window.

In plain terms:

- User → Cloudflare: **OK**
- Cloudflare → Origin: **timed out**

This is not a Cloudflare outage. It is almost always a problem between Cloudflare and your origin.

## Four common causes

### 1. Origin firewall blocking Cloudflare IP ranges

This is the most frequent cause.

When Cloudflare proxies traffic, it connects to your origin from its own IP ranges, not from the visitor's IP. If your origin server's firewall, security group, or WAF does not allowlist Cloudflare's published IP ranges, every incoming connection from Cloudflare is silently dropped.

The origin still looks healthy from your local machine or monitoring because those requests arrive from different IP addresses.

**How to verify**: check your origin firewall rules for port 80 and 443. Confirm Cloudflare IP ranges are explicitly allowed.

### 2. Origin server overloaded

When CPU usage spikes, connection backlog fills up, or your application server runs out of worker threads, the origin can no longer accept new TCP connections — even though the process is technically still running.

Intermittent 522 errors during high-traffic periods are a strong signal for this cause.

**How to verify**: check origin CPU, memory, connection count, and Nginx/application error logs at the time of the 522 events.

### 3. Network or routing problems at the origin

Cloud provider network events, recent security group changes, or unstable origin routing can block inbound traffic from Cloudflare's edge nodes even if the origin is reachable from elsewhere.

This is the hardest cause to diagnose locally, because your own network path to the origin is different from Cloudflare's.

**How to verify**: use a Cloudflare Trace to confirm which Cloudflare edge node is handling requests, then test origin connectivity from a server in the same region.

### 4. DNS pointing to the wrong origin

If the A record in Cloudflare's DNS dashboard points to an old server, a decommissioned IP, or an internal address that Cloudflare cannot reach, the connection will time out regardless of origin health.

**How to verify**: check the DNS A record in the Cloudflare dashboard. Confirm the IP matches the currently running origin server.

## Recommended diagnosis order

When you see a 522, work through this checklist before changing anything:

1. **Check origin port 80 / 443**: is the service actually listening? (`ss -tlnp` or `netstat`)
2. **Check firewall rules**: are Cloudflare IP ranges allowed inbound on 80 and 443?
3. **Check origin load**: CPU, memory, active connections, and Nginx worker status at the time of the error.
4. **Check DNS records**: does the A record in Cloudflare point to the correct server?
5. **Check Nginx / application logs**: are there corresponding incoming request entries, or no entries at all? No entries means the connection was blocked before reaching the app. Entries with errors point to an app-level problem.

Step through the list in order. The answer is almost always in steps 1–4.

## 522 vs other Cloudflare 5xx errors

| Code | Meaning |
|------|---------|
| 521 | Origin refused the TCP connection |
| **522** | **TCP connection timed out before completing** |
| 523 | Origin unreachable (DNS failure or no route) |
| 524 | Connection established, but origin took too long to respond |
| 525 | SSL handshake failed between Cloudflare and origin |
| 526 | Cloudflare could not validate the origin SSL certificate |

A 522 sits between 521 (outright refusal) and 524 (slow response). Each code points to a different layer of your stack, so the distinction matters for fast triage.
